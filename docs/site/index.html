HakiOS on Phone (1)

A Darwin/XNU research port with verified iOS RAM boot through Mu-Silicium and U-Boot. Physical touch and volume work with 550 MHz graphics; persistent dual boot remains unfinished.

Verified phone build

Display1080 × 2400 home screen and wallpaper
InputSingle-contact touch, power and volume keys
CPUSeven XNU cores; CPU0 serves USB
GraphicsAdreno 642L, Mesa/OpenGL ES at 550 MHz

The user confirmed smoother rendering with touch and buttons working. The quiet build retains debugging code and has no scheduled run cutoff. Long-duration stability and multitouch remain unverified.

Wi-Fi, audio, microphone, cameras, vibration, battery reporting, charging, Bluetooth, cellular and persistent data are not established working Phone (1) features. Metal drawing is not verified; the working graphics path is OpenGL ES.

Run the verified RAM build

Build with your own matching firmware, DTB and iOS images, or use your locally verified bundle. Put the phone into stock Android fastboot and run from Windows platform-tools:

.\fastboot.exe boot .\xnu-spacewar-gpu-clocks.img
powershell -NoProfile -ExecutionPolicy Bypass -File .\spacewar-userland-gpu.ps1 -Touch -Quiet -GpuMHz 550

The launcher saves live logs beside the images. Ctrl+C stops the host collector; fastboot oem stop requests return to the loader. A reboot returns to Android.

U-Boot and dual boot

Installation is not validated. The linker BSS-placement error is corrected. The USB diagnostic build with stdin=nulldev reached fastboot and supplied a console log. The console initialization-order fix also enabled the custom menu and physical volume/power navigation. USB fastboot and console retrieval work after menu selection; startup tracing is off in the quiet menu.

The full U-Boot → EFI loader → XNU → iOS RAM path is phone-verified at 550 MHz; the user confirmed touch/volume and no log text in the quiet run with debugging off. The touch driver now preserves the idle RSC IRQ state under the exclusive loader lease, and its controller-RAM firmware upload passed ECC/runtime checks. Firmware USB status/debug output defaults off.

USB and full console capture were verified in diagnostic runs. Quiet-run live-log stability remains unverified; its collector did not fetch a first snapshot within 60 seconds.

The separate read-only storage profile reaches USB fastboot, but UFS/SCSI discovery returns -6. Loading from storage remains unvalidated, and the storage kernel is not phone-tested. No partition writes were performed; a phone-specific partition plan and verified backups come before installation.

Use hardware keys to return to stock Android fastboot. Software reboot to the Android bootloader is unsupported in these RAM profiles; reset bootloader only resets the phone.

The existing RAM menu image is tested with fastboot boot. It does not install a second system or change the active slot. No 20 GiB partition, slot-b Android setup or persistent 12 GB data volume is established for Phone (1).
